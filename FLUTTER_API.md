# Простыми словами: что это за проект и какой API можно дать Flutter-приложению

Этот файл написан так, чтобы его понял человек, который вообще не участвовал в разработке этого проекта — но которому нужно на основе этого файла сделать своё (например, Flutter-приложение). Поэтому здесь всё объясняется с нуля, без «и так понятно».

---

## Часть 1. Что вообще такое этот проект

### 1.1 Что такое «Telegram-бот» вообще, если коротко

Telegram-бот — это не «умный собеседник» вроде ChatGPT. Это обычная программа на сервере. Когда человек пишет боту сообщение или нажимает кнопку, Telegram пересылает это на сервер разработчика, сервер решает, что ответить (по заранее написанному коду), и отправляет ответ обратно через Telegram. То есть весь «ум» бота — это код на сервере, а Telegram — просто почтальон между человеком и этим сервером.

### 1.2 Какую конкретно проблему решает этот бот

Представь обычную компанию. У неё есть рабочие группы, которые регулярно встречаются (планёрки, обучение, отделы — не важно). Проблема: никто нормально не фиксирует, кто реально пришёл на встречу, кто за что отвечал, и что происходит с посещаемостью за неделю в целом — обычно это либо не фиксируется вообще, либо кто-то вручную ведёт табличку и постоянно забывает.

Этот бот берёт всю эту рутину на себя:

1. **До встречи** — бот сам публикует объявление о встрече в Telegram-канал группы (тема, дата, время, кто за что отвечает).
2. **Во время встречи** — ответственный человек открывает бота, видит список участников с кнопками, и нажатием кнопки отмечает: пришёл / не пришёл / не пришёл по уважительной причине.
3. **После встречи** — бот сам публикует итоги в тот же канал: кто был, кто нет.
4. **Раз в неделю (по субботам)** — бот сам считает статистику за неделю по каждому человеку и публикует сводку в канал.
5. **Отдельно** есть человек-наблюдатель — он не состоит ни в одной группе, но должен видеть общую картину по всем группам сразу. Для него сделан отдельный экран со статистикой (об этом — в части 3).

### 1.3 Кто есть кто в этой системе (роли)

Важно понять: **один и тот же человек может одновременно иметь несколько ролей**. Например, один и тот же человек может быть одновременно «Секретарём» и «Техническим сотрудником» — это нормально, не ошибка.

| Роль (как называется в коде/боте) | Что это значит по-человечески | Что может делать |
|---|---|---|
| **Moderator** (Модератор) | Руководитель конкретной рабочей группы | Создаёт встречи, назначает роли другим участникам этой группы |
| **Kotib** (Секретарь) | Тот, кто ведёт учёт на встрече | Отмечает, кто пришёл, а кто нет |
| **Jarayon eksperti** | Эксперт процесса | Просто роль-метка, отображается в списках и в постах канала |
| **Texnik xodim** | Технический сотрудник | Просто роль-метка |
| **Taqdimotchi** | Докладчик | Просто роль-метка |
| **Ishtirokchi** (Участник) | Обычный участник, у которого нет никакой другой роли | Ничего особого не делает, просто числится в группе |
| **Kuzatuvchi** (Наблюдатель) | Человек «сверху», который не состоит ни в одной группе | Смотрит встречи/участников/статистику **любой** группы, но ничего не меняет |

### 1.4 Как выглядит обычный рабочий день с этим ботом — пошагово

Чтобы совсем было понятно, вот конкретный пример «от первого лица»:

1. Сотрудника добавили в компанию. Он пишет боту `/start`, вводит своё имя, должность, делится номером телефона через кнопку Telegram (не печатает вручную). Дальше администратор компании (человек, а не бот) вручную добавляет этого сотрудника в нужную рабочую группу через отдельную веб-страницу (не через бота — про это ниже).
2. Модератор группы открывает бота, нажимает «Yangi uchrashuv» («Новая встреча»), вводит тему, выбирает дату/время нажатием на кнопки календаря, выбирает формат (очно/онлайн). Всё — встреча создана, и бот сам постит объявление в канал группы.
3. Когда время встречи подошло, ответственный (модератор или секретарь) открывает бота, видит кнопку «отметить посещаемость», и для каждого участника по очереди нажимает: пришёл / не пришёл / уважительная причина.
4. Ответственный нажимает «завершить встречу» — бот сам считает итоги и публикует их в канал: списком, кто пришёл, а кто нет.
5. В субботу бот сам, без чьего-либо участия, публикует в канал сводку за неделю по каждому человеку.
6. Наблюдатель в любой момент открывает бота, нажимает «Статистика» — открывается отдельная веб-страница внутри Telegram с карточками по каждой группе и цифрами посещаемости.

## Часть 2. Из чего технически состоит проект

Проект написан на языке PHP, с использованием фреймворка Yii2, данные хранятся в базе PostgreSQL. Но для понимания сути детали языка программирования не так важны — важнее понять, что в проекте есть **три отдельных «входа»**, и они не связаны друг с другом как единое целое:

### 2.1 Вход первый — сам Telegram-бот
Telegram присылает на сервер каждое сообщение/нажатие кнопки через механизм, который называется **вебхук** (webhook) — это просто означает «Telegram сам стучится на наш адрес в интернете каждый раз, когда что-то происходит», в отличие от других способов, где сервер бы сам постоянно спрашивал Telegram «есть что-то новое?». Этот вход предназначен только для общения с Telegram, больше ни для чего не годится.

### 2.2 Вход второй — веб-панель администратора
Это обычный сайт (открывается в браузере, не в Telegram), защищённый логином и паролем. На этом сайте администратор компании вручную:
- создаёт рабочие группы и привязывает к ним Telegram-каналы,
- добавляет туда людей (тех, кто уже зарегистрировался в боте через `/start`),
- назначает модератора группы,
- может создавать/редактировать/удалять встречи и отметки посещаемости вручную, если что-то пошло не так.

Этот сайт отдаёт обычные HTML-страницы (то есть готовые веб-страницы для просмотра человеком в браузере), а не данные в формате, который могла бы использовать другая программа (например, Flutter-приложение).

### 2.3 Вход третий — веб-страница статистики внутри Telegram (Mini App)
Для наблюдателя сделана отдельная веб-страница, которая открывается **прямо внутри Telegram** по нажатию кнопки в боте (это называется Telegram Mini App / Web App — фактически обычная веб-страница, которую Telegram показывает во встроенном окошке, не выходя из приложения). Эта страница обращается к серверу и получает данные в формате **JSON** (см. часть 3, что это такое) — и это единственное место в проекте, где сервер вообще отдаёт данные в машиночитаемом виде, а не в виде готовой HTML-страницы.

**Важная тонкость:** даже эта JSON-страница защищена так, что её может открыть только сам Telegram — при открытии Telegram передаёт странице специальный подписанный код (`initData`), и сервер проверяет: этот код действительно от настоящего Telegram или кто-то подделал запрос. Обычное отдельное приложение (например, Flutter-приложение, которое не открывается изнутри Telegram) не может получить такой код — значит, оно физически не сможет воспользоваться даже этим единственным существующим JSON-эндпоинтом. Сервер ему просто ответит «отказано» (код ошибки 401).

**Вывод:** сейчас в проекте нет ни одного API, которым могло бы воспользоваться отдельное Flutter-приложение. Всё, что есть, — либо только для Telegram, либо только для браузера с логином/паролем.

## Часть 3. Что такое API вообще, и что нужно сделать, чтобы Flutter мог им пользоваться

### 3.1 Что такое API — объяснение с нуля

Представь ресторан. Ты (посетитель) не идёшь на кухню готовить сам — ты смотришь в меню, выбираешь блюдо по названию, официант уносит заказ на кухню, а тебе приносят готовое блюдо. **API — это и есть такое меню**: список того, что можно «заказать» у сервера (например, «дай мне список встреч этого человека»), и в каком виде придёт «блюдо» (ответ).

Технически это выглядит так: приложение (Flutter) отправляет запрос на определённый адрес (например, `https://адрес-сервера/api/meetings`), сервер обрабатывает его и присылает ответ в формате **JSON** — это просто текст, оформленный по строгим правилам, который любая программа (Flutter, веб-сайт, что угодно) умеет читать и превращать в свои данные. Пример JSON:

```json
{
  "id": 5,
  "topic": "Weekly Planning",
  "date": "2026-08-15 10:00",
  "format": "offline"
}
```

Это просто «список пар ключ-значение» — ничего сложного, просто договорённость о формате.

### 3.2 Что такое «авторизация по токену» — тоже с нуля

Сервер должен понимать, **кто именно** делает запрос (иначе кто угодно мог бы посмотреть чужие данные). Для сайта (веб-панель администратора) это решается через логин/пароль и «сессию» в браузере (браузер сам помнит, что ты уже вошёл). Для мобильного приложения так не работает — у Flutter нет браузерных «сессий». Вместо этого используется **токен**: один раз человек логинится, сервер выдаёт ему длинную секретную строку (токен), и дальше при каждом запросе Flutter-приложение просто прикладывает эту строку («вот мой токен, я — такой-то пользователь»), а сервер проверяет её и понимает, кто спрашивает.

Сейчас в проекте такого механизма (выдачи токена не через Telegram) **нет вообще** — это придётся сделать с нуля.

### 3.3 Что нужно реализовать на сервере, чтобы Flutter мог работать

По шагам, что нужно **добавить в код** (сейчас этого нет):

1. **Способ входа (логина) не через Telegram-виджет внутри Telegram.**
   Проще всего — использовать [Telegram Login Widget](https://core.telegram.org/widgets/login): это кнопка «Войти через Telegram», которую можно встроить прямо в экран логина Flutter-приложения (через встроенный браузер). Telegram сам подтверждает личность человека и передаёт подписанные данные — по тому же принципу, что уже реализован для Mini App, только для отдельного приложения. Дальше сервер выдаёт токен.

2. **Новые адреса на сервере, которые отдают JSON** (сейчас таких, доступных извне Telegram, нет). Ниже — конкретный список, что имеет смысл сделать, с примерами.

### 3.4 Готовый список API-эндпоинтов, которые стоит сделать

Это не то, что уже работает — это план того, что нужно написать на сервере, чтобы Flutter мог этим пользоваться. Для каждого — что он делает, какой запрос отправляет Flutter, и что примерно отвечает сервер.

---

**Вход в приложение**

`POST /api/auth/telegram`
Что делает: принимает данные от Telegram Login Widget, проверяет их подлинность, находит (или создаёт) пользователя и выдаёт токен.
Ответ:
```json
{ "token": "eyJhbGciOi...", "user": { "id": 12, "full_name": "Alisher Karimov" } }
```

`GET /api/me`
Заголовок запроса: `Authorization: Bearer <токен>`
Что делает: возвращает профиль текущего пользователя.
Ответ:
```json
{
  "id": 12,
  "full_name": "Alisher Karimov",
  "phone": "+998901234567",
  "language": "uz",
  "is_observer": false,
  "groups": [ { "id": 1, "name": "Marketing", "roles": ["moderator"] } ]
}
```

---

**Группы**

`GET /api/groups`
Что делает: список групп, где состоит пользователь (или все группы — если это наблюдатель).
Ответ:
```json
[ { "id": 1, "name": "Marketing" }, { "id": 2, "name": "Sales" } ]
```

`GET /api/groups/{id}/members`
Что делает: участники группы и их роли.
Ответ:
```json
[
  { "id": 12, "full_name": "Alisher Karimov", "roles": ["moderator"] },
  { "id": 13, "full_name": "Dilnoza Yusupova", "roles": ["kotib", "texnik_xodim"] }
]
```

---

**Встречи**

`GET /api/meetings?group_id=1`
Что делает: список встреч группы.
Ответ:
```json
[ { "id": 5, "topic": "Weekly Planning", "date": "2026-08-15 10:00", "format": "offline", "status": "announced" } ]
```

`POST /api/meetings` (только для Модератора группы)
Что отправляет Flutter:
```json
{ "group_id": 1, "topic": "Weekly Planning", "date": "2026-08-15 10:00", "format": "offline" }
```
Что делает сервер: создаёт встречу, публикует анонс в Telegram-канал группы.

`POST /api/meetings/{id}/cancel`
Что отправляет Flutter: `{ "reason": "Переносится на другую дату" }`
Что делает: отменяет встречу, постит в канал сообщение об отмене.

---

**Посещаемость**

`GET /api/meetings/{id}/attendance`
Что делает: текущие отметки по каждому участнику этой встречи.
Ответ:
```json
[ { "user_id": 12, "full_name": "Alisher Karimov", "status": "present" }, { "user_id": 13, "full_name": "Dilnoza Yusupova", "status": null } ]
```

`POST /api/meetings/{id}/attendance` (только Модератор/Секретарь)
Что отправляет Flutter: `{ "user_id": 13, "status": "present" }` (варианты статуса: `present` — пришёл, `absent` — не пришёл, `excused` — по уважительной причине)

`POST /api/meetings/{id}/finish`
Что делает: закрывает отметку присутствия и публикует итоги встречи в канал.

---

**Статистика (для наблюдателя)**

`GET /api/stats?group_id=0&period=a`
`group_id=0` значит «по всем группам сразу», `period` — `a` (за всё время), `w` (эта неделя) или `m` (этот месяц).
Что делает: то же самое, что уже считает часть кода на сервере для веб-страницы статистики внутри Telegram — эту часть можно переиспользовать напрямую, она уже не завязана на Telegram, просто нужно разрешить вызывать её и с обычным токеном тоже, а не только из Telegram.
Ответ:
```json
{
  "groups": [
    {
      "id": 1, "name": "Marketing", "meetings": 4,
      "members": [ { "name": "Alisher Karimov", "present": 3, "absent": 1 } ]
    }
  ]
}
```

### 3.5 Итог: что конкретно нужно сделать программисту, чтобы всё это заработало

1. Добавить вход через Telegram Login Widget + выдачу токенов (раздел 3.3, пункт 1).
2. Написать новый раздел кода на сервере с адресами из раздела 3.4 — сейчас их не существует, их нужно создать с нуля.
3. Перенести проверки «этот человек — модератор этой группы» / «это секретарь» из кода бота в общее место, чтобы и бот, и это новое API проверяли права одинаково, без дублирования логики.

До тех пор, пока это не сделано, у Flutter-приложения нет данных, к которым можно подключиться — весь функционал, описанный в части 1, существует только внутри Telegram-бота и веб-панели администратора.
