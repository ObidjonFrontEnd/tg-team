- [x] Роли участника «по умолчанию» на уровне группы (таблица `group_member_roles`) — Модератор меняет их через бота (тап на участника → toggle-клавиатура ролей). **Это единственное место, где меняются роли** — при создании встречи роли больше не выбираются (см. ## Этап 3. Планирование и анонс встреч

- [x] Интерфейс создания встречи — **упрощён до 3 шагов**: тема → дата/время → формат → встреча тут же создаётся. Выбор участников и ролей убран из мастера (по фидбеку: «он быстро создаёт встречи», а роли — это шаблон группы, не разовый выбор)
- [x] Участники встречи — автоматически все участники группы; роли — автоматически из группового шаблона (`group_member_roles`), см. Этап 2
- [x] **Inline-календарь** для выбора даты/времени (`dayPickerKeyboard`/`timePickerKeyboard`) — кнопки на 14 дней вперёд + кнопки часов, вместо обязательного ввода текста. Кнопка «✏️ Boshqa sana/vaqt» — резервный путь для свободного ввода
- [x] Гибкий парсинг даты/времени (`BotHandler::parseMeetingDate`) — принимает разные разделители и однозначные день/месяц/час/минуту, не только строгий `YYYY-MM-DD HH:MM` (используется в резервном ручном вводе)
- [x] Валидация регламента: встречу нельзя создать позже чем за **12 часов** до её начала (`BotHandler::MIN_ADVANCE_HOURS`) — упрощено с исходного 24ч/12ч-при-срочности до единого минимума в 12ч по прямому запросу заказчика. Отключается для тестовых пользователей (см. «Отклонения»)
- [x] Отмена встречи Модератором (`Meeting::STATUS_CANCELLED`) — сохраняется в БД, пропадает из активных списков (встречи/посещаемость)
- [x] Отмена в 2 шага: обязательная причина текстом → подтверждение Да/Нет (защита от случайного нажатия). Причина + кто/когда отменил сохраняются в БД (`meetings.cancel_reason/cancelled_by/cancelled_at`, миграция `m260807_000011`)

## Отклонения от исходного плана (сделаны автономно ради скорости — можно пересмотреть)

1. **Telegram-библиотека:** свой HTTP-клиент вместо `irazasyed/telegram-bot-sdk` — меньше риска несовместимости версий, проще поддерживать при таком объёме вызовов API (sendMessage/editMessageReplyMarkup/answerCallbackQuery).
2. **Локализация:** тексты захардкожены в `services/Texts.php`, а не вынесены в `messages/uz/*.php` (штатный Yii2 i18n). Раз язык всего один и меняться не будет — полноценный i18n была бы лишней сложностью. Если понадобится второй язык — тогда стоит перейти на `Yii::t()`.
3. **Проверка прав бота в канале** при создании группы не выполняется автоматически (не блокирует создание группы) — считаем, что админ сам добавил бота в канал заранее. Можно добавить позже через `getChatMember` с bot user_id.
4. **Управление группами полностью перенесено в веб-админку** (по прямому запросу заказчика) — бот больше не даёт создавать/вступать в группы самостоятельно; только просмотр (участники, встречи, роли) и действия внутри уже назначенной группы.
5. **Отметка посещаемости запускается вручную** (кнопка в меню, не крон), но **с проверкой времени**: пункт появляется в списке, только когда встреча уже началась, и пропадает через 12 часов после начала (см. Этап 4) — компромисс между «нет частого крона» и «нельзя отмечать что попало когда попало».
6. **Валидация «встреча не позже чем за 24ч/12ч»** реализована в упрощённом виде — единый минимум **12 часов** (без деления на «обычная/срочная» встреча).
7. **П. 2.3.1 регламента** (присутствие менее половины времени → «не пришёл») не реализовано — бот не отслеживает время входа/выхода, только финальный статус, который выставляет Kotib/Moderator вручную.
8. **Веб-админка** защищена одним логином/паролем из `.env` (без таблицы пользователей/ролей на уровне веб-доступа) — достаточно для одного администратора; при необходимости нескольких админов с разными правами понадобится полноценная auth-таблица.
9. **Тестовый обход временных ограничений** (`TEST_BYPASS_TELEGRAM_IDS` в `.env`) — по запросу заказчика для тестирования Davomat/создания встреч без ожидания 12-часового окна. **Важно очистить эту переменную в проде**, иначе указанные пользователи смогут создавать встречи и отмечать посещаемость в обход регламента.

Если что-то из этого списка критично — скажи, поправим в первую очередь.
